# D-build kickoff — the checklist for when gate(D) goes true

*The bridge from the field phase back to the keyboard. Two audiences: **[F]** boxes are
the founder's, **[A]** boxes belong to the coding agent's first session. Authority
order from here (the D brief's own rule): the **adopted spec artifact** governs over
`docs/handoff_dispatch_d.md`, which governs over habit — the spec has finding
provenance and a governance signature; nothing else does.*

---

## 1 — [F] Verify the gate is real (ten minutes)

```
[ ] mix harness.status → gate=true, no short legs
[ ] BuildStarted{section: "D"} is on the log (it appended when you ran
    mix harness.build_started — if it isn't there, the gate never opened; stop)
[ ] mix harness.checkpoint → published OFF-MACHINE (the gate's truth, committed
    where you can't quietly rewrite it)
[ ] the three adoption hashes recorded where you can hand them over:
    spec ____________  defaults ____________  model ____________
```

## 2 — [F] Counsel head start (start now — these block go-LIVE, not the build)

```
[ ] counsel_briefing.md Tier 2 formally opened: dunning wording (2.1), detention
    line-item posture (2.2), transmission authorization language (2.3)
[ ] answers plug in later as templates and an H5 envelope form; the build proceeds
    meanwhile — nothing in Tier 2 gates a commit, only the first real send
```

## 3 — [F] The first hub (the demo runs on a real carrier's books — 13 §6)

```
[ ] which founding carrier's operation the D slice goes live on: agreed, by name,
    with them — their prospect consent already covers the conversation
[ ] their document channel agreed (v0 is manual import: forwarded mailbox dumps or
    file drop — no connectors, per the brief; their formats become real fixtures)
[ ] the envelope conversation had IN PRINCIPLE: their co-3 answer will become the
    default they SIGN (H5 — their signature, their ceiling; nothing activates
    itself); the signing itself waits for 4A's machinery
[ ] expectation set honestly: first value is paperwork + detention evidence on
    their own books, reviewed artifacts not auto-sends, weeks not days
```

## 4 — [F→A] The handoff (what the agent's first prompt should contain)

```
[ ] repo access + suite green (mix test — 203+)
[ ] pointer to docs/handoff_dispatch_d.md
[ ] the three hashes from step 1
[ ] one paragraph of field color the log can't carry: which carrier is the hub,
    anything counsel flagged, anything you promised them
```

## 5 — [A] The agent's first session (before any code)

```
[ ] verify the gate independently: BuildStarted on the log; Log.verify_chains :ok;
    the latest published checkpoint verifies
[ ] fetch all three artifacts by hash (Artifacts.get), hash-verify (the store does),
    decode; the fixture bundle enumerates and every fixture is text
[ ] READ the adopted spec end to end: nodes, tiers, the embedded classifier (the
    operator's why-judgment), the adversarial cases (real war stories — every one
    becomes a test)
[ ] transcribe the 4A slice into docs/phase4a_plan.md — envelope machinery + tender
    rail — flagging EVERY divergence between the spec and the brief's sketch (the
    spec wins; the flag is the record)
[ ] note the blocks without touching them: block-tier nodes stay blocks until a
    phase plan reclassifies them with evidence and a signature — never silently
[ ] plan committed before build; steps committed when the full suite is green;
    deviations flagged never silent (the convention that built everything so far)
```

## 6 — Standing disciplines for the whole build (both of you)

```
spec > brief > habit · out-of-envelope escalates (the 5A rail is waiting — its ε
denominator arrives with your act streams) · parses are proposals, never authoritative ·
the fixture set is the parser's TDD corpus · no connectors, no auto-sends in v0 ·
money never moves — settlement is the obligation rail · every demo number is a fold
over the FULL stream (13 P2: the founder cannot cherry-pick their own pitch)
```

## 7 — What "done" means, phase by phase (from the brief's acceptance)

```
4A envelope + tender rail: routing replays identically; revocation atomic;
   out-of-envelope never acts; parser green against the published fixtures
4B dispatch + tracking: an unbroken load lifecycle; dwell is a fold; no check-call
   machinery exists (the node is deleted, not automated)
4C invoice + detention + dunning: invoices byte-reproducible; detention lines carry
   evidence hashes; every external act has its compensator
4D demo kit + guards: the hub's open-book, hours-returned, and detention-recovered
   folds — live, recompilable, and the founding campaign's proof (13 §3)
```

Then the invitation wave — because a demo that doesn't run isn't a demo, and by 4D's
last green test, it runs.
