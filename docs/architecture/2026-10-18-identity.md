# Identity: principals, providers and sessions

Date: 2026-10-18. Status: **implemented** in `BizKit.Identity`
(`apps/biz_kit_identity`) and SpruceGoose's `AuthController`; WorkOS is the
first provider.

## Decision

> WorkOS authenticates. Biz-kit identifies. CoopSubstrate authorises. Buzz
> collaborates.

| Concept | Owner | What it answers |
| --- | --- | --- |
| Principal identity | biz-kit (`BizKit.Identity`) | who the person or agent is inside the platform |
| Authentication | a provider (WorkOS today) | that someone proved they are a given `{issuer, subject}` |
| Authorisation | the CoopSubstrate ledger | what a principal may do: its grants |
| Collaboration | Buzz | what people see and do |

A principal exists independently of how it signs in. Replacing the provider
changes how sessions start. It does not change principals, signing keys,
grants or history.

Rejected: using WorkOS user IDs as ledger principals, which would tie every
grant and every historical event to one vendor. Deferred: WorkOS
Fine-Grained Authorization (a second permission system to keep in sync with
the ledger), self-hosting an identity provider, and a Nostr-to-Ed25519 bridge
for Buzz.

## Pieces

- **Principals** (`Principal`): `prn_` and 128 random bits in lowercase
  base32, minted by biz-kit. Ledger grants name these IDs.
- **Providers** (`Provider` behaviour): `authorize_url/3` (the sign-in page)
  and `authenticate/3` (a returned code becomes a verified
  `%{issuer, subject}`, the OpenID Connect pair). Nothing else crosses the
  boundary. `Providers.WorkOS` exchanges the AuthKit code server-side with the
  API key. Its issuer is `https://api.workos.com/user_management/<client_id>`
  and its subject is the WorkOS user ID.
- **Resolver** (`Resolver`): `{issuer, subject}` → principal, through
  explicit bindings only, never email or any other attribute. One principal
  may have several bindings (several providers, or a migration in progress).
  Malformed bindings refuse every resolution and refuse boot. Bindings are
  administrator-controlled configuration for now (`BIZKIT_IDENTITY_BINDINGS`,
  JSON). They are expected to become governance-signed link/unlink events on
  the ledger, with the resolver reading their projection.
- **Sessions** (`Sessions`): local, issued after sign-in, one hour by
  default. They can be revoked one at a time (logout) or for a whole
  principal. A session's identity is resolved again on every use, so
  unbinding an identity ends its sessions immediately. Sessions are held in
  memory, in one process for the whole [cluster](2026-10-19-cluster.md): a session works on every
  node, and a restart of that process signs everyone out.

Native apps get the same session as a bearer token through a brokered
RFC 8252 sign-in ([native sign-in](2026-10-21-native-sign-in.md)).

## HTTP (SpruceGoose)

```
GET  /auth/:provider/login     302 to the provider; state in an HttpOnly cookie
GET  /auth/:provider/callback  state checked, session cookie set, 302 to :after_login_path
POST /auth/logout              session revoked, 204
```

The session cookie (`bizkit_session`) is HttpOnly and SameSite=Lax, and
Secure unless `:secure_cookies` is off (tests only). The feed accepts it in
place of a signed request (see the
[change feed](2026-10-18-change-feed.md#access)). Refusals are a bare `401`;
the reason goes to the log.

Configuration: `WORKOS_CLIENT_ID`, `WORKOS_API_KEY`,
`BIZKIT_IDENTITY_BINDINGS`, `SPRUCE_GOOSE_PUBLIC_URL` (for the callback
address).

## What a session cannot do

A session authenticates reads. It never signs a command. Writes, such as
accepting or declining a suggestion, still need an Ed25519 signature from a
key named in the principal's operator grant: a per-device key held by the
browser or the Tauri app. No server signs in a person's name. Device keys
belong to the principal, not the provider, so they survive a provider change
too.

## Verification

- `BizKit.IdentityTest`: principal IDs; the WorkOS authorize URL and code
  exchange (stubbed with `Req.Test`), including a refused code; the resolver
  matches only bound pairs and refuses malformed or duplicate bindings;
  sessions are issued only to bound identities and end on logout, at expiry,
  on unbinding and per principal; changing provider keeps the principal.
- `SpruceGoose.Web.AuthTest`: the login redirect carries the state; the
  callback refuses a forged or missing state, an unbound identity and an
  unknown provider; the feed refuses a session whose principal has no grant
  on the project, a forged cookie and a revoked grant; a live stream ends on
  logout.
- **Acceptance (portability):** a person signs in through WorkOS and their
  device creates a task under their grant. The administrator then binds
  their identity at a second provider to the same principal and unbinds the
  WorkOS one. The WorkOS session's stream ends and the session is refused.
  Signed in through the second provider, the same principal reads the same
  project, sees its history, and the same device key creates another task
  under the same grant. Both ledger events name the same principal.
- Mutations: not resolving the identity again on each session use, not
  checking the session during a stream, or not checking the login state each
  fails a test.
