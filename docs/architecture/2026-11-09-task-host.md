# The task host: SpruceGoose's web surface, rehosted

Date: 2026-11-09. Status: **implemented**. The first rehosting step of the
[SpruceGoose decommission checklist](2026-11-06-sprucegoose-decommission.md)
(§1, Surfaces). It does not fence SpruceGoose's writers (§2) or retire its
history (§3).

## Decisions (owner, 2026-11-09)

1. **A new `task_host` app**, not a host shared with `restaurant_host`. Hosts
   stay thin and deploy on their own; composition wires the domains.
2. **Native sessions are kept.** The store moves into identity, and the
   table stays where it is. No device has to sign in again.
3. **`/mcp` and SpruceGoose's OAuth2 issuer are dropped.** They exposed
   SpruceGoose's own Ash resources, which retire with it. If an agent needs
   MCP later, it is rebuilt on task commands.

## What moved where

| Was | Is | Notes |
| --- | --- | --- |
| `SpruceGoose.Web.*` (router, endpoint, 14 controllers, `Requests`, `RateLimit`) | `TaskHost.Web.*` | Moved with `git mv`; every decision is still `CoopSubstrate`'s or `BizKit.Identity`'s |
| `/auth` (web and native sign-in) | `TaskHost.Web.AuthController` | The one authentication entry point outside SpruceGoose |
| `SpruceGoose.Web.NativeSessionStore` | `BizKit.Identity.PostgresSessionStore` | Reads its repo from `:biz_kit_identity, :session_repo` (`TaskHost.Repo`) |
| `identity_native_sessions` | unchanged | `TaskHost.Repo`'s migration has SpruceGoose's version, `20261021120000`. On SpruceGoose's database it is already applied, so the rows stay |
| `priv/static/app`, `test/browser`, `test/js` | `apps/task_host/…` | The web view and its browser and unit tests |
| `mix coop.blueprint`, `SourceVerifier`, `ForgejoVerifier` | `apps/task_host` (`TaskHost.Blueprints.*`) | SpruceGoose's legacy blueprint commands use them through a `runtime: false` dependency until it retires |
| `/mcp`, OAuth2 issuer, `ActorPlug`, `Oauth*` resources | removed | Their tables are kept, never dropped; `ash_ai` and `ash_authentication_oauth2_server` leave the lock |

SpruceGoose keeps its legacy writer, its Ash resources and its CLI service
(`SPRUCE_GOOSE_CLI_SERVICE_ENABLED`). It binds no HTTP port.

## Deployment

- **Releases.** `biz_kit` and `orchestration` carry `task_host`. Run
  `bin/orchestration eval "TaskHost.ReleaseTasks.migrate()"` before each start,
  alongside SpruceGoose's own; both initialize the ledger idempotently.
- **Port.** The endpoint binds loopback, as SpruceGoose's did, on
  `TASK_HOST_PORT` (default 4001). A deployment that set `MCP_PORT` keeps that
  port. It now starts without `SPRUCE_GOOSE_MCP_ENABLED`, which no longer
  exists.
- **Database.** `TASK_HOST_DATABASE_URL`, or `DATABASE_URL`, so by default the
  database SpruceGoose used.
- **Unchanged names.** Settings the host inherited keep their names until
  decommission: `SPRUCE_GOOSE_PUBLIC_URL`, `SPRUCE_GOOSE_TRUSTED_PROXIES`,
  `SPRUCE_GOOSE_SIGN_IN_LIMIT`, `SPRUCE_GOOSE_FORGEJO_*` and
  `SPRUCE_GOOSE_BLUEPRINT_MAX_BYTES`.
- **Custody bytes.** Ledger custody receipts name bytes under
  `:coop_substrate, :artifact_dir`. Before this change no release set it, so
  it was `priv/artifacts` relative to the release's working directory.
  `COOP_ARTIFACT_DIR` now names it. Set it, and carry the bytes along when a
  deployment moves. This is the checklist's "receipts stay readable" gate.
  `ARTIFACT_STORE_ROOT` is only SpruceGoose's legacy store.
