# SCF accounting host: écritures on the canonical Log

Status: implemented on this branch; tested against PostgreSQL 16 and the real
Log. Not deployed. Not reviewed by an Algerian accountant or tax adviser (see
"Before production" in `apps/scf_core/SIGNED_PROJECTION.md`).

## Decision

Algerian (SCF) books are written through `CoopSubstrate.Log` like every other
business fact, not into a host-owned database. One rulebook,
`ScfCore.SignedProjection`, decides both **admission** and **rebuild**:

```
accountant ─ signed posting ─▶ Log.append
                               ├─ Scf.duplicate   (exact retry → original event)
                               ├─ Scf.live_check  (time window, grant, session,
                               │                   SignedProjection.admit on the
                               │                   chain-assigned row)
                               └─ AdmissionGate   (Scf.fold!: same admit, signed time)
host ─ signed read ──────────▶ Log.scf_book      (grant checked in the mailbox)
     ─ ScfCore.Reports/Statements ─▶ journal, balance, TCR, bilan, G50
```

A posting is admitted iff the fold would post it, using the full-record
digest and positions the Log has just assigned. The gate's book is therefore
exactly the fold of the admitted log. A test compares it with an offline
`ScfReplaySource.capture` plus `SignedProjection.replay`.

## Events (`CoopSubstrate.Scf`, stream `private-scf/<entity_id>`)

| Type | Signer | Meaning |
| --- | --- | --- |
| `ScfBookOpenedV1` | governance | One book per chapter/entity; first exercice |
| `ScfAccountantGrantedV1` | governance | Entity-scoped `scf_accountant` key: versioned, expiring, revocable |
| `ScfJournalEntryPostedV1` | accountant | General écriture: journal, date, libellé, pièce (id + SHA-256), DZD lines |
| `ScfServiceRevenueRecognizedV1` | accountant | 411/706 from an earlier `InvoiceIssued` (no TVA) |
| `ScfEntryReversedV1` | accountant | Contrepassation of an exact earlier posting |
| `ScfFiscalYearClosedV1` | accountant | Clôture through 31 December of the open year |
| `ScfBookReadV1` | accountant | Read request; never appended |

Every accountant event carries `command_id`. Retries are idempotent per book.
Changed content under a known id is `scf_idempotency_conflict`. Postings are
singleton batches. Live admission requires a signature within 30 s of the
appender clock and a current grant and session. Replay uses signed time, so
later revocation never erases admitted entries. `InvoiceIssued` events are
folded into an entity's book only once the book is open.

`scf_core` is a **runtime** dependency of `coop_substrate` (pure,
dependency-free). This deviates on purpose from procurement's optional kernel.
A release that shares the store but lacks the rules would otherwise fail
closed at Log boot as soon as one SCF event exists.

## Host (`apps/scf_host`, release `scf`)

* **Console** (French, server-rendered): journal with contrepassation,
  saisie d'écriture (8 lines, chart datalist, amounts typed `1 234,56`),
  balance générale, compte de résultat and bilan with clôture, and the TVA
  position for the G50.
* **API** `/api/v1`: `GET journal`, `GET statements?from&to|mois`, and
  `POST commands` with `{kind: entry|reversal|close, command_id, …}`.
* **Access** follows the procurement pilot: one accountant per deployment, a
  console token and an optional API token configured as SHA-256 digests, and
  a server-held signing key granted independently on the ledger.
  Sessions use encrypted Secure/HttpOnly/SameSite=Strict cookies (4 h); forms
  are CSRF-protected; responses are no-store with a restrictive CSP. Every
  request re-reads the book under the ledger grant, so revocation is
  immediate.
* **Pièces**: an uploaded file is hashed and its bytes are discarded. Only
  the id and SHA-256 enter the log. **There is no document store yet**, so
  retention and retrieval of the justificatifs remain the operator's job.

Configuration: `SCF_ENABLED=true`, `SCF_PORT` (4090), `SCF_CHAPTER`,
`SCF_ENTITY`, `SCF_ACCOUNTANT`, `SCF_KEY_ID`, `SCF_SIGNING_SEED_HEX`,
`SCF_GRANT_VERSION`, `SCF_LOGIN_SHA256`, `SCF_API_SHA256` (optional),
`SCF_SECRET_KEY_BASE`, `SCF_DATA_DIR`, and `EVENTSTORE_*`. The listener binds
to loopback; terminate TLS in front of it.

## Not yet

A document store; enrollment tooling for book opening and grants;
multi-entity or multi-accountant consoles; à-nouveaux and affectation du
résultat; TVA-bearing revenue recognition; G50 beyond TVA; liasse fiscale.
There is also no packaged-release acceptance runner of the procurement kind.
