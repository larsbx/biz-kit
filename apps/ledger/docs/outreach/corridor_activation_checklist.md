# Corridor activation — the checklist for when both ends are ready

*The corridor is the unit; cities are halves (02 §2: each activation adds O(n) lane
pairs, and outreach was corridor-paired from the first email so that ends arrive
together — 12 §2). This checklist is lock-shaped like everything else: the corridor
goes live when every lock is open, and **no lock is opened by wanting it to be**. The
first corridor is also the capacity moat's first proof — the driver theorem stops being
a formula and starts being someone's Tuesday night at home.*

---

## 1 — Constants lock (declare before anything evaluates — the standing rule)

```
[ ] m_c and f_c — activation thresholds (locus per the spawn decision: federation-
    standard or chapter-declared, 02 §6.2)
[ ] daily_range — THE forced one: the driver theorem (∀ leg: length ≤ daily_range ⇒
    driver sleeps at home, 02 §2) is unevaluatable without it, and leg assignment
    policy evaluates it on every match. Open in the corpus since day one (02 §6.1);
    this corridor forces it. Declare per the session template.
[ ] if yards are leased: u_min, d_min, L_max already live from the T2 waking session —
    verify, don't re-declare
```

## 2 — Evidence lock (per end; queried, never asserted)

```
[ ] members(end A) ≥ m_c — from the fold      [ ] members(end B) ≥ m_c
[ ] flow_fold(A) ≥ f_c                        [ ] flow_fold(B) ≥ f_c
[ ] if either fold says no: the corridor isn't ready and this checklist adjourns —
    the answer is recruitment and demand work at the short end, never a lower constant
```

## 3 — Yards lock (per end — staging is what makes a corridor a corridor)

```
[ ] a staging yard per end, honestly placed on the ladder: coop_leased (T2 gate G₁→₂
    passed — pledges before signature, 03) ∨ member_owned ∨ prospect-with-terms
[ ] operable(yard) true — the 06 §2 predicate, fail-closed, fresh within τ
[ ] ≥ G2 on the security bits BEFORE any loaded trailer stages (07 §2 — a member
    walked the lot and attested fences and lighting; Rosa's gate, kept)
[ ] custody machinery exercised: a rehearsal drop and hook, dual-signed, chains
    verified — the same rehearse-on-the-real-log trick as the field kickoff
```

## 4 — Coverage & liability lock (the hard one; do not soften it)

```
[ ] every participating carrier: tenderable(c) true (06 §2)
[ ] relay-leg liability assignment at yard boundaries: DECIDED — the corpus left it
    open (02 §6.1 → 06 extension) and no relay leg can responsibly assign without it.
    This is the corridor's counsel-and-maybe-ruling moment: [INSURANCE] terms per leg,
    and if any instrument shape is contested, it enters at N and waits (09). A
    corridor with unassigned liability is not a corridor; it is a lawsuit with yards.
[ ] insurer notice: staging and relay patterns disclosed per the coverage counsel
    items — surprises void coverage, and coverage predicates only check what's true
```

## 5 — Rails lock (the software both ends run)

```
[ ] dispatch workflows live at both ends (the D slice per chapter; gate(D) discipline
    traveled with the spec — ratified by hash at end B, not re-discovered)
[ ] participating carriers' envelopes SIGNED for corridor legs (H5 — their lanes,
    their floors, their ceiling; the chapter offered, the member opted)
[ ] the geometry shown to the drivers it affects: each target leg's length vs the
    declared daily_range, on one page — home-daily is a theorem only when the
    numbers are real (and the 13A qualifier holds: where geometry and freight
    support it)
```

## 6 — Treaty lock (cross-chapter corridors only)

```
[ ] the inter-chapter agreement signed per the template — mirror events, both logs
[ ] mirrored-custody discipline briefed to the members actually doing handoffs
[ ] mutual witness running (Article 6): first checkpoints exchanged
```

## 7 — The activation act

```
[ ] every lock above open → each end's governance declares, on its own log:
      CharterConstantDeclared{ name: "corridor/<A>-<B>/active", value: 1,
                               note: <counterpart end / agreement hash if treaty> }
    (the declared-constant pattern again — a dedicated corridor event type is a
    later nicety; provenance is complete today)
[ ] checkpoints emitted both ends; exchanged if cross-chapter
[ ] the announcement discipline flips FOR THIS CORRIDOR ONLY: "in a live corridor"
    (13A's load-bearing qualifier) is now true here — pitch assets that cite corridor
    folds rebuild from the live folds (12 P1: assets recompile, never hand-edit)
```

## 8 — Day-one watch (the corridor proves itself or it doesn't)

```
[ ] the first relay handoff: dual-signed hook, chains verified same day
[ ] dwell folds at both yards — watched, not assumed
[ ] the detention claim (02 P5): staged, coverage-cleared endpoints REMOVE the
    live-load detention category — day one starts the evidence that this corridor's
    endpoints actually do; exceptions surface as logged events, never silently
[ ] weekly status gains a corridor block: legs run, home-daily nights actually
    slept, exceptions — the driver theorem's proof is a count of beds
```

## 9 — Deactivation honesty (say it at activation, like the exits everywhere)

Evidence fades ⇒ folds fall ⇒ gates go false ⇒ matching suppresses — a corridor winds
down the way it woke, automatically, and in-flight loads complete under the terms they
started with. Nobody needs a meeting to stop what the evidence stopped. Reactivation is
this same checklist, fresh folds.
