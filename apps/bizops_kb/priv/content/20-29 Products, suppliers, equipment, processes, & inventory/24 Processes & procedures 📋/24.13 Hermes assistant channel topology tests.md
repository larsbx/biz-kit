# Hermes assistant channel topology tests

Compare Buzz plus one inbound channel at a time, in this order:
**T1 Buzz + Telegram**, **T2 Buzz + WhatsApp**, **T3 Buzz + SMS**. Each run uses
the same test suite, so results compare row by row. The winner becomes the
primary channel in [[24.12 Hermes assistant on-site deployment]]; until then,
its Telegram default is provisional.

Runs use a test stack from [[24.12e Hermes assistant hosting model]] (slug
`test`), test accounts and numbers only, and no client data.

## Setup per topology

| | T1 Telegram | T2 WhatsApp (Baileys) | T3 SMS |
| --- | --- | --- | --- |
| Credential | Bot token | Linked device on a **throwaway number**; a ban must not touch a real number | Provider account + number |
| Documents (test 6) | Native; bot file downloads cap at 20 MB | Native media | Not carried: test the upload-link path instead (MMS out of scope) |
| Extra checks | Bot privacy mode in groups | Session expiry and re-link; duplicate deliveries after reconnect | Segmentation over 160 characters; delivery receipts; cost per message |
| Expected weak point | Telegram outage | Bridge stability | No attachments; unencrypted |

## Shared test suite

| # | Test | Pass criterion |
| --- | --- | --- |
| 1 | Round-trip: employee → channel → Buzz → agent → reply | Reply arrives; record p50 and p95 latency over 20 messages |
| 2 | Intake record | Each message appears in Buzz exactly once, stamped with channel and sender |
| 3 | Idempotency | The same message delivered twice yields one task and one reply |
| 4 | Identity | Enrolled sender reaches their own profile; unknown sender gets catch-all only |
| 5 | Loop prevention | The agent's reply in Buzz is not ingested again as new inbound |
| 6 | Document intake | Channel → Buzz → librarian → filed in the correct tier |
| 7 | Restricted refusal | Restricted file in chat is refused and the upload link is returned |
| 8 | Channel outage | Failure is visible, not silent; after recovery nothing is lost or duplicated |
| 9 | Buzz outage | Record what the channel does: queues, errors, or drops |
| 10 | Revoke | Removing the sender from the allowlist stops replies at once |

## Decision rule

A topology qualifies as primary only if tests 2–5, 7, and 10 all pass. Among
qualifying topologies, prefer the lowest p95 latency, then document support
(test 6), then outage behaviour (tests 8–9). Record the outcome here and update
the primary channel across the 24.12 notes in the same change.
