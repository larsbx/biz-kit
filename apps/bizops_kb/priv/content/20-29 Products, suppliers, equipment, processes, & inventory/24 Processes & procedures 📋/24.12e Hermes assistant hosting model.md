# Hermes assistant hosting model

Part of [[24.12 Hermes assistant on-site deployment]].

## Decision

**We host the cloud zone; each client company gets its own isolated stack.**
One stack = that company's Buzz relay, its database, and its Hermes runner and
gateway, co-located on our hardware. Companies never share a Buzz instance,
a Hermes volume, a bot token, a phone number, or a key.

| Option | Verdict | Why |
| --- | --- | --- |
| Client self-hosts | Rejected | Their internal admin would operate prototype software; the runbook already routes all cloud-zone work to us |
| We host, one shared instance for all clients | Rejected for now | Buzz rate limiting is a test stub, so one tenant can starve the rest; a shared WhatsApp number means one ban hits every client; per-community isolation is unproven |
| **We host, one stack per company** | **Adopted** | Blast radius of one company; per-company backup, restore, and removal; near-identical cost at ~20 users per company |

Revisit shared hosting only after Buzz's community isolation passes
adversarial testing (Buzz roadmap Phase 8).

## Stack template

Every name carries the company slug `<co>` (lowercase, no spaces).

| Component | Instance | Notes |
| --- | --- | --- |
| Buzz relay + database | `buzz-<co>` containers, own volume | Own community, own relay keys |
| Hermes runner | container `hermes-<co>-runner`, volume `hermes-<co>-home` | Credentials live only in the volume |
| Hermes gateway | container `hermes-<co>-gateway` | Own Telegram bot, own WhatsApp number, own SMS number |
| Host port | one unique loopback port per company | Recorded in the tenant register below |
| Edge pod | `<co>-edge`: Tailscale, Syncthing, Quartz builder, Caddy | Serves the company's ICM and wiki on its tailnet; holds the intake outbox Hermes writes to |
| Office Syncthing configs | `<co>-office`: one `config.xml` per office device | Department folders per [[24.12f Hermes assistant office file plane]]; generated with the edge config |
| Office link | the company's own Tailscale tailnet | Never joined to another company's tailnet |

The edge pod and the office configs are built from
`native-deployment-control-plane/ops/tenant-edge` (one `tenants.nix` entry per
company); see its README for deploy and distribution.

Hermes takes the per-company names from its own environment file, so no code
changes are needed. `~/.config/hermes-podman/<co>.env` holds **non-secret
selection only**:

```sh
HERMES_PODMAN_ENVIRONMENT=production
HERMES_PODMAN_VOLUME=hermes-<co>-home
HERMES_PODMAN_CONTAINER=hermes-<co>-runner
HERMES_PODMAN_GATEWAY_CONTAINER=hermes-<co>-gateway
HERMES_PODMAN_PORT=<port>
```

Run every command for that company with
`HERMES_PODMAN_ENV_FILE=~/.config/hermes-podman/<co>.env scripts/hermes-podman <command>`.

Buzz and Hermes run in separate containers on the same host and talk over
loopback only. Restricted documents never reach the cloud zone: they stay in
the company's office-zone vault.

## Per-company lifecycle

**Onboard a company**

1. Pick `<co>` and a free port; add a row to the tenant register.
2. Create the Buzz relay and database for `<co>`.
3. Write `<co>.env`; build or reuse the image; run `onboard` with the
   company's own bot token and numbers; then `deploy`.
4. Wire ingress into that company's Buzz only; run the test suite from
   [[24.12 Hermes assistant on-site deployment]].
5. Schedule that company's backups; perform one restore before go-live.

**Offboard a company**

1. Export their data if the contract requires it; hand it over.
2. `stop`; remove the `<co>` containers and volumes; revoke the bot token,
   release the numbers, delete relay keys.
3. Delete their backups when the retention period in the data processing
   agreement ends.
4. Mark the register row closed with the date.

## Data terms

Hosting the cloud zone makes us the processor of each client's chats and
documents. Before go-live, the client signs a data processing agreement
covering: what we store (chats, routed documents below restricted tier), where
it is hosted, retention, backup, breach notification, and deletion on exit.
The owner sign-off records it ([[24.12d Hermes assistant owner sign-off]]).
