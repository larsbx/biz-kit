# Experimental gossip wire conformance vectors

`gossip_wire_v1.json` contains deterministic **public test keys**, signed
Create/Update/Delete advertisements, an exact-content freshness lease, a catch-up
offer and a receiver receipt. Never use these seeds or key pins in a deployment.
No fixture message is a real publication or attestation of stored data.

The vectors are generated by `../support/gossip_reference.py`, a standalone
Python 3.12 implementation using only its standard library and OpenSSL 3's
Ed25519 command interface. It imports no Elixir, Rust or application code and
does not start a network listener. Private test-key DER files are temporary and
removed on exit. Expected public keys are supplied separately to verification;
the embedded publisher key is not treated as its own trust root.

From the repository root:

```sh
python3 apps/federation_service/test/support/gossip_reference.py verify \
  apps/federation_service/test/vectors/gossip_wire_v1.json
python3 -m unittest discover -s apps/federation_service/test/support \
  -p 'gossip_reference_test.py' -v
python3 apps/federation_service/test/support/gossip_reference.py generate > /tmp/gossip-wire-v1.json
cmp /tmp/gossip-wire-v1.json apps/federation_service/test/vectors/gossip_wire_v1.json
```

The fixture includes exact transcript bytes in lowercase hex, topic ID, content
and batch commitments, Unicode text, control escaping, null Delete metadata,
maximum safe integers and canonical key-order probes. Its epoch is deliberately
2^53−1. UTF-8 ordering differs from UTF-16 ordering for the included U+E000 and
astral object keys. Composed/decomposed strings remain distinct. Arrays retain
their order. No Unicode normalization, ASCII-only escaping, whitespace or
trailing LF is added to canonical bytes. Hex digits inside JSON control escapes
are uppercase; short escapes are used for backspace, tab, LF, form feed and CR.
Quote and backslash are escaped; slash, U+2028/U+2029 and other Unicode scalars
remain literal UTF-8. Floats and non-string object keys are outside this
canonical subset, as are malformed UTF-8 and unpaired surrogate values.

`GossipWireTest` admits the independent messages through the real Elixir
receiver, checking projection, strict freshness, revision replacement,
withdrawal and exact content. The fixed receipt test explicitly installs the
known outgoing manifest because the normal sender uses a random round nonce;
the same receipt is refused before that manifest exists. Separately, the normal
sender API creates a random round and the actual receiver durably completes it.
All four live Elixir message types are exported to the independent verifier.
The actual signed receipt is then admitted by the sender. Source-event counts
remain unchanged by control messages, and the receiver has no business events.

The Python negative controls corrupt signatures in every message type, expected
pins, commitments and transcripts, including a correctly re-signed offer with
an incorrect batch commitment; duplicate/deep/oversize/non-JSON input and
unsupported canonical types also refuse. CI runs these controls and both
directions of the Elixir tests, alongside the real two-process QUIC test.
Focused service tests now require `python3` and `openssl` on PATH.

This is an independent **wire conformance oracle**, not a second production
node. Its checks cover known message shapes, transcript construction, Ed25519
signatures, explicit expected keys, scope/actor correspondence, content hashes
and offer batch hashes. It does not implement the full Marketplace validator,
network admission, time/current-pin policy, replay state, moderation or durable
receiver evidence. In particular, verifying a signed receipt alone proves no
storage or current possession. Live third-party peer interoperability, public
NAT/relay operation, Halaqa adoption and ActivityPub conformance remain open.
